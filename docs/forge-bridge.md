# `window.Forge` – native capabilities for packaged web apps

Available only inside an app generated by Forge, on the app's own origin and only for the top-level page (not iframes).
Feature-detect it: `if (window.Forge) { ... }`. Every method returns a Promise.

| Method | Enabled by | Result |
|---|---|---|
| `Forge.googleSignIn({ nonce? })` | "My site uses Google sign-in" | `{ idToken, email, name, givenName, familyName, photo }` |
| `Forge.googleSignOut()` | same | `{}` |

Errors are `Error` objects with `.code`: `CANCELLED` (user closed the sheet), `NO_CREDENTIAL` (no Google account on the device),
`FAILED` (message has details, usually a Google Cloud setup problem), `UNSUPPORTED`.

## Google sign-in setup (what the wizard checks for you)
1. Google Cloud Console → Credentials: a **Web client** (its Client ID goes in Forge) and an **Android client** with your package id and SHA-1.
   Use the upload key's SHA-1 for builds you sign yourself, and the *App signing key certificate* SHA-1 from Play Console for the published app.
2. Verify `idToken` on your server (audience = the Web Client ID), or hand it to Firebase Auth with `GoogleAuthProvider.credential(idToken)`.

## Why not sign in inside the page?
Google refuses OAuth in embedded WebViews (`disallowed_useragent`). The bridge uses Android's Credential Manager, the official native sheet.
In Forge's own preview there is no bridge; use the 🌐 button to test the web flow in Chrome at `http://localhost:8080`
(add it to *Authorized JavaScript origins*).
